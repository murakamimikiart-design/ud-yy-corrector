# UDトーク × YYprobe 半自動修正補助ツール

YYprobe の正確な文字起こしを「正」として、UDトークの誤りだけを直すための補助アプリ。
イベント本番（9月13日）で、運営が最短の手数で字幕を直せることを最優先に作っている。

---

## クイックスタート

### いちばん確実な使い方：ブラウザ版（推奨）

Finder で **`uy_corrector.html` をダブルクリック**。Safari か Chrome で開きます。それだけです。

- Python も追加インストールも不要
- ネット接続も不要（ファイル1つで完結。会場のWi-Fiが不安定でも動く）
- どの Mac でも、iPad でも、Windows でも同じように開ける
- 会場のPCに配るときは、この 1 ファイルをコピーするだけ

### 予備：Python 版（tkinter）

```bash
python3 uy_transcription_corrector.py
```

Finder で `起動.command` をダブルクリックでも起動します。
**環境によってウィンドウが正しく動かないことが確認されています**
（macOS 標準の Python に同梱される Tk が古いため）。
また、選択方式が旧仕様（YYを採用するか否かの2択のみ・自分で入力する機能なし）のままです。
本番はブラウザ版を使ってください。

### 動作確認（差分ロジックのテスト）

```bash
python3 test_diff_engine.py
```

`OK` と出れば正常。GUI を開かずに確認できるので、本番前のチェックに使う。
ブラウザ版の差分ロジックは、この Python 版と同じ結果になることを確認済み。

## 画面の使い方

※ブラウザ版・Python 版とも画面構成は同じ。

```
┌─────────────────────┬─────────────────────┐
│ UDトーク（公開に使う側）│ YYprobe（もう一方）  │  ← ここに貼り付ける
├─────────────────────┼─────────────────────┤
│ どちらが正しい？       │ 公開される文          │  ← 箇所ごとに選ぶ
│  [UD案] [YY案] [✎]   │  緑=YY 青=自分で入力  │
├─────────────────────┴─────────────────────┤
│ 最終テキスト → 「これで決定 → コピー」        │
└───────────────────────────────────────────┘
```

**YYprobe は「正解」ではない。** 実際に試すと UD が正しいことも、YY が誤字することもある。
そのため差分は「誤り一覧」ではなく **「どちらを採るかの選択肢」** として出る。
両方とも違うときは ✎ を押して自分で入力する。

| 要素 | 説明 |
|------|------|
| 左「UDトーク」 | UDトーク編集画面からコピーしたテキストを貼る（最終的にここへ戻す） |
| 右「YYprobe」 | YYprobe の認識結果を貼る |
| どちらが正しい？ | 食い違った箇所ごとに **[UDトーク案] [YYprobe案] [✎]** が並ぶ。クリックで選ぶ |
| ✎ ボタン | 両方とも間違っているとき。押すと入力欄が出て、正しい言葉を打てる |
| 全部 UD／全部 YY | 全箇所を一括で片側に寄せる（ほぼ全部が片方正しいときに速い） |
| 公開される文 | 選んだ結果。**緑＝YYを採用／青＝自分で入力／色なし＝UDのまま** |
| 最終テキスト | 公開する文そのもの。ここを直接書き換えてもよい |
| これで決定 → コピー | 最終テキストを確定してクリップボードへ。あとはUDトークに貼るだけ |
| UD欄に反映して次へ | 決定した文を左に移し、右を空にして次の発話へ |
| サンプル読込 | 練習用の例を順に読み込む（UDが正しい例・両方誤る例も入っている） |
| 大きく＋／小さく－ | 文字サイズ変更（会場の見え方に合わせる） |
| 句読点の違いは無視 | ON なら「、。」や全半角の差は食い違いに数えない（既定 ON） |
| 自動で比較 | ON なら貼り付けた瞬間に比較（既定 ON） |
| 言い回しの差も表示 | OFF のとき、ひらがな・記号だけの差（「ね、」「って」等）を一覧から隠す（既定 OFF） |

既定では全箇所が **YY 側を選んだ状態**で出る。UD が正しい箇所だけクリックして UD に戻す、
という使い方が一番速い。

### 「言い回しの差」を隠す理由

実データ（2026/09/09、動画音声30秒）で試すと **19箇所**の食い違いが出た。
内訳は、語そのものの誤り（「車学習者→手話学習者」「送り歯→コクリハ」）が10箇所、
残り9箇所は「ね、」「って」「では」のようにUDが拾いきれなかっただけの言い回しだった。

本番で19箇所を1件ずつ判断するのは不可能なので、ひらがな・記号だけの差は
一覧から隠している（**結果には YY 側が反映済み**なので、隠れていても文は直る）。
判断が必要な語の誤りだけが一覧に残る。全部見たいときはトグルをONにする。

|------|------|
| `⌘Return` | これで決定 → コピー |
| `⌘V` | 各欄をクリックしてそのまま貼り付け |

## 当日の運用フロー

```
1. YYprobe のテキストをコピー → アプリの右欄に貼り付け
     ↓
2. UDトーク編集画面のテキストをコピー → アプリの左欄に貼り付け
     ↓
3. 食い違った箇所が並ぶ。1箇所ずつ、どちらが正しいか耳で判断して選ぶ
     ・UDが正しい → [UDトーク案] をクリック
     ・YYが正しい → そのまま（既定でYY）
     ・両方違う   → [✎] を押して正しい言葉を入力
     ↓
4. 「これで決定 → コピー」（⌘Return）
     ↓
5. UDトークに貼り付け ＝ これが公開される字幕
     ↓
（「UD欄に反映して次へ」で次の発話へ）
```

**重要：** このツールは判断しない。**正誤を決めるのは人**で、ツールは
「食い違っている箇所はここ」と示して選ばせるだけ。最終的に公開されるのは
常に UDトーク側であり、そこへ何を流すかは決定ボタンを押した人が決める。

## ライブ比較（Chrome拡張）

**UD側もYY側もブラウザで読み取り、コピペなしで比較する。**

| 側 | 配信の出し方 | ページ | 拡張機能側 |
|---|---|---|---|
| UDトーク | トーク公開画面の「ウェブで公開」 | `live.udtalk.jp/…` | `panel.js`（比較パネル本体） |
| YYProbe | 文字起こし画面 左上のQRアイコン | `analytics.yyprobe-demo.com/meeting-viewing-mode…` | `yy.js`（読み取って共有） |

`yy.js` が YY の発話を `chrome.storage.local` に書き、UD 側の `panel.js` が受け取って
比較する。2つのタブ（またはウィンドウ）を開いたままにしておけばよい。

### 1発話単位で直す（重要）

UDトークは**1発話ずつ**編集する。一方 UD と YY では発話の区切りがまるで違う
（UDは細かく切れ、YYは長くつながる）。そのため複数発話をつなげて直すと、
貼り付けたときに前後の発話まで入り込んで**文が重複する**。

そこでパネルは「直す発話を1つ選ぶ → その発話に対応するYYの箇所を自動で切り出す →
その発話だけを直す」形にしている。コピーされるのは常に1発話ぶんだけ。

対応箇所の切り出し（`alignAll`）は、発話ごとに個別に探すのではなく、
**全発話をまとめて時系列で対応付け、境界で切り分ける**。
個別に探すと範囲が前後にはみ出し、隣の発話ぶんまで拾ってしまうため
（実データで確認済み：ある発話に対して、直前の発話ぶんまで拾ってしまっていた）。

`window.__udyyDebug`（alignAll / compare / fold）から、実ページ上で切り出し結果を確認できる。

YYの配信ページはルビが付かないので、そのまま取り出せる。日本語側は
`.default-content .remark-content-div`、翻訳側（`.foreigncontent`、`d-none` で非表示）は使わない。

**YYのタブは裏に回るため、Chrome のタイマー制限を避けて時刻ベースで更新している。**

### ドメインについて
検証時のYY配信URLは `analytics.yyprobe-demo.com` だった（名前に demo が入っている）。
本番アカウントで別ドメインになる場合は `chrome_extension/manifest.json` の
`matches` に追記して、拡張機能を再読み込みすること。

### 入れ方
`chrome://extensions` →「デベロッパー モード」ON →「パッケージ化されていない拡張機能を読み込む」
→ `chrome_extension` フォルダを選択。以降、公開ページを開くと自動で表示される（`option+U` で開閉）。

### なぜブックマークレットではないか
同じコードをブックマークレット化すると約2万文字になり、**Chrome ではブックマークに入れても
実行されなかった**（ブックマークレット自体の動作はテストページで確認済みなので、
コードではなく Chrome 側の保存の問題）。小さい「取り出しボタン」は約4千文字で、こちらは使える。

### 使い方の要点
**直している間も取り込みは止めない。** 発話を1つ指定して直す方式なので、
選んだ発話は固定され、裏では次の発話が入り続ける。止めてしまうと、
直し終わったときに遅れを取り戻せなくなる。

そのために次の3つを入れてある。
- 選んだ発話が直近N件から流れ出ても、一覧に残して選択を保つ
- 比較の中身が変わっていなければ作り直さない（選んだ内容が消えないように）
- ✎ に入力している最中は作り直さない

「自動取得: 固定」ボタンは残してあるが、手動で止めたいとき用。

`copy` イベントを拾っているので、**⌘C だけでも最終テキストがコピーできる**。
範囲選択があるときは横取りせず、通常のコピーに任せる。

## UDトークの「ウェブで公開」ページから取り出す（任意）

UDトークでトークを「ウェブで公開」すると `live.udtalk.jp/…` のページが発行され、
ブラウザで認識結果が読める。**ただしこのページの漢字にはふりがな（ルビ）が振られており、
普通にコピーすると「担当たんとう」のようにルビが本文に混ざる。**

`UD取り出しボタン.html` を開き、ブックマークバーに入れておくと、公開ページ上で
ワンクリックしてルビを除いた素のテキストを取り出せる（最新1件／3件／全部）。

- 公開ページはアプリ起動用リンク（`service.udtalk.jp/redirect.php`）とは別物。
  発行元は UDトークの公開画面の「ウェブで公開」ボタン
- パスコードを設定した場合は、ブラウザで先にログインしてから使う
- UDトーク側のページ構造が変わると動かなくなる可能性がある。補助なので、
  動かなければ従来どおり編集画面からコピーすればよい

YYprobe には同等の web 公開機能が見当たらないため、**YY側は手動コピーのまま**。

## トラブルシューティング

### Q. Python 版でウィンドウは出るのに操作できない
macOS 標準 Python の Tk が古いことが原因。**ブラウザ版（`uy_corrector.html`）を使う。**
機能は同じで、こちらは動作確認済み。

### Q. ブラウザ版で「コピー」が効かない
ブラウザがクリップボードを拒否した場合、下の「修正済みテキスト」欄を
クリックして `⌘A`（全選択）→ `⌘C` でコピーできる。

### Q. ブラウザ版で「貼り付け」はどうやる？
左右の欄をクリックして `⌘V`。ブラウザなので普通の貼り付けがそのまま使える。

### Q. 「貼り付け」ボタンが効かない
クリップボードが空か、他アプリがコピーを完了していない可能性。
テキスト欄を直接クリックして `⌘V` でも貼り付けられる。

### Q. 差分が細かすぎる／大きすぎる
`diff_engine.py` の `compare(..., gap=1)` を調整する。
`gap` を大きくすると近い変更同士がまとまり、小さくすると細かく分かれる。

### Q. 直したくない箇所まで直ってしまう
修正候補リストでその項目をクリックして選択を外す（グレーになる＝不採用）。
「すべて不採用」を押せば UD 原文がそのまま残る。

### Q. 句読点の違いばかり出てくる
「句読点の違いは無視」を ON にする（既定 ON）。

### Q. 本番でアプリが落ちた
アプリ無しでも運用は止まらない。UDトーク編集画面で従来どおり手修正に切り替える。
アプリは補助であり、字幕配信そのものには関与しない。

## 技術仕様

### 構成
```
uy_corrector.html               # ブラウザ版（手で貼り付ける版）
chrome_extension/               # ★Chrome拡張（公開ページ上でライブ比較）
udtalk_live_panel.js            # 同上の中身。編集後は build_extension.command で反映
build_extension.command         # 拡張機能へ反映するスクリプト
UD取り出しボタン.html            # UDトーク公開ページ用ブックマークレットの導入ページ
udtalk_grabber.js               # 同上のソース（保守用）
uy_transcription_corrector.py   # 予備の Python 版（tkinter）
diff_engine.py                  # 差分ロジック（GUI非依存・単体テスト可能）
test_diff_engine.py             # 単体テスト 13 件
testdata/samples.json           # 練習用サンプル（誤認識の実例を追記していく）
起動.command                     # Python 版のダブルクリック起動用
legacy_pysimplegui_prototype.py # 初版プロトタイプ（PySimpleGUI 版・参考用）
```

ブラウザ版はサンプルを HTML の中に埋め込んである（`file://` から外部ファイルを
読み込めないため）。`testdata/samples.json` に実例を足したときは、
ブラウザ版の `SAMPLES` にも同じものを足す。

### 差分検出
- 比較前に正規化：空白・句読点を無視（任意）、NFKC で全半角を揃える。
  正規化後の位置は原文の位置に戻すので、**表示・置換は常に原文ベース**。
- `difflib.SequenceMatcher` を文字単位で適用。
  日本語では差分が細切れになるため、間の一致が `gap` 文字以下なら 1 件に結合する。
- 各変更は `replace` / `delete` / `insert` として保持し、**採用したものだけ**を
  UD 原文に差し込んで修正済みテキストを作る（`apply_changes`）。

### 性能
数百〜数千文字であれば体感ゼロ。貼り付け後 350ms のデバウンスで自動比較する。
